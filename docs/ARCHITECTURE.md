# Architecture

Moved from CLAUDE.md (#202): the integration model, each heuristic, the dispatch and parallel infrastructure, `ContestedPdlp` and the shared utilities. CLAUDE.md keeps a short map and links here; the rules here bind exactly as they did there.

## Architecture

**Integration model**: two layers (#170). The HiGHS source is fetched at build time (v1.15.1) with patches applied from `third_party/highs_patch/`.

- **`mip_heuristics_core`** (STATIC): the algorithms (FJ and LocalMIP with their runners, FPR's search with `prop_engine`/`walksat`/`repair_*`), `SolutionPool` and `SolutionSink`, the runner scaffold (`ContinuousLoopState`, `run_opportunistic_loop`, `attempt_with_rebuild`, `WorkerBudgetState`, `Deadline`) and the model view (`heuristic_context.h`). **It needs no `HighsMipSolver`**: it includes no `mip/` header but the header-only `mip/feasibilityjump.hh`, and links `libhighs` (`$<LINK_ONLY:highs>`) but needs only its utility code from it — the timer, the sparse transpose, the logger and the task executor, as the checks below enforce. A caller that owns its model gets a view from `make_problem(const HighsLp&, ProblemStorage&, feastol, epsilon)`, builds its own `ExecutionContext`, and subclasses `SolutionSink::on_accept` as its sink. To run FJ or LocalMIP on a thread it owns until it says stop, it calls `fj::run_until_stopped` / `local_mip::run_until_stopped` (#171; contract beside `RestartSource` in `heuristic_context.h`): one worker slot on the calling thread, stopped through `ExecutionContext::stop`, a stalled worker rebuilt through `attempt_with_rebuild` from the caller's `RestartSource` before the sink's pool. It is `run_opportunistic_loop`'s own slot loop (`run_slot`) driven by `run_on_caller_thread`, not a second loop, and the presolve dispatch passes an empty source through the same rebuild code. A caller that wants LocalMIP's least-violated infeasible point (ReXi's LNS start while its pool is empty, #188) points `ExecutionContext::least_violated` at a `LeastViolatedPoint` (`least_violated.h`): each worker keeps a running total violation through `apply_move` (uncharged, gated on the pointer) and offers its least-violated state on its deadline-poll cadence; null, the default and the adapter's, measures nothing. Two more opt-ins serve the same reproduction (#189): `get_restart`'s `RestartPolicy::kBestOnly` (pool and sink) restarts from the best entry alone, drawing nothing, where the default `kMixed` keeps the crossover draw; and `ExecutionContext::restart_now`, asked before every `run_until_stopped` attempt, rebuilds the worker from the source at once when it returns true — the margin rule is the caller's. The presolve dispatch never reads `restart_now`, and reaches `kBestOnly` only through `HeuristicBudget::restart` below. FJ's worker patience (`worker_stale`, presolve and `run_until_stopped` alike) reads upstream FJ's own `effortSinceLastImprovement` alone, which restarts at a new fewest violated rows, never effort since the sink's best moved: that one retired FJ before its first feasible solution however fast its violations fell (#191). `HeuristicBudget::fj_stall_ends_run` (default off; SCIP feasjump's one run, for mip-concurrent's root FJ) makes a retired FJ worker end the `run_until_stopped` run instead of being rebuilt. FJ's stall is read only at upstream's callback, so it is never seen sooner than 500000 effort units in (#194): accepted, since HiGHS's own FJ, the reference ahead of SCIP for FJ, has the same floor. What a *rebuild* restarts from (never a slot's first worker) is `HeuristicBudget::restart` (#200), a `RestartPoint`: `kDefault` as above, `kBest` the source's point else the pool's best else the incumbent, unperturbed, and `kHybrid` that base with each column redrawn within its bounds half the time (`hybrid_restart`, Local-MIP v2's); both are resolved by `rebuild_restart_point`, and fall back to `kDefault` with no base. `HeuristicBudget::randomize_restart_weights` (LocalMIP) starts a rebuilt worker's weights, half the time, at draws from {1, 2}. Every draw of either sits behind its option, so the defaults move no RNG stream. Three checks enforce the boundary. The ctest `core_boundary` (`cmake/check_core_boundary.py`) makes two: every header a core translation unit reaches, as the compiler lists it (`-M` with the unit's own flags from `compile_commands.json`, so a `mip/` header reached through `presolve/HPresolve.h` counts), is a core header, a non-`mip/` HiGHS header or `mip/feasibilityjump.hh`; and a simulated whole-archive link of the core against `libhighs.a` — every symbol the archive leaves undefined, resolved member by member and followed transitively — pulls in no member built from `highs/mip/` and no adapter object; a failure names each offending core member and the symbol it needs, demangled, and `--chains` prints the full path to every forbidden member (`Highs::run` is in `Highs.cpp` and reaches the MIP solver only from there). The build makes the third: `mip_heuristics_core_standalone_tests` (`tests/test_core_standalone.cpp`) links the **whole** core archive (`$<LINK_LIBRARY:WHOLE_ARCHIVE,...>`) against `libhighs_without_mip.a`, a copy of `libhighs.a` with every `mip/` member and every adapter object removed (`cmake/strip_archive.cmake`), so it does not link at all if any core member needs either. **Keep it whole**: an ordinary archive link extracts only the members the test's cases reach, and a dependency in any other core member links unseen — its cases build their model by hand, since the `Highs` class itself reaches the MIP solver. **A new core file goes in the core target's list, headers included**, or the include check cannot see it. `mip_heuristics_core_tests` (`tests/test_core.cpp`) links the core alone and runs FJ and LocalMIP to a feasible solution on a model read with `Highs::readModel`; both core test files check every solution against the `HighsLp` itself (its column-wise matrix, integrality, sense and offset), never against the view.
- **`mip_heuristics`** (OBJECT, injected into `highs`): the adapter — `mode_dispatch`, `IncumbentSink`, `effort_ledger`, `highs_context.h` (the view, `ExecutionContext` and `Deadline` built from a live solver), FPR's dispatch and clique rankings (`fpr.cpp`, `fpr_var_order`, `clique_cover`), `fpr_lp`, Scylla and `ContestedPdlp`. It accesses HiGHS internals directly via `HighsMipSolver&`.
- **`libhighs` holds both layers**: `highs` takes the adapter's objects and the core's (`$<TARGET_OBJECTS:...>`), so it is self-contained, as before the split, and a plain `-lhighs` link (pkg-config, or any build system but CMake) resolves. The core library is the same objects again, for a caller that wants the core without the adapter; a link naming both archives pulls each object once. **Do not link the core to `highs` instead**: the two archives would each need the other, a cycle CMake orders but a `.pc` file cannot, because pkg-config collapses the repeated `-lhighs` it needs. The core is installed into HiGHS's own export set (`install(TARGETS ... EXPORT highs-targets)`, plus `export(... APPEND FILE highs-targets.cmake)` for the build tree) with its headers under `include/mip_heuristics`, so a `find_package(highs)` consumer gets `highs::mip_heuristics_core` beside `highs::highs`. Both targets are compiled with exactly the flags the single library had — a split that changed a heuristic's compile command would be a behaviour change to prove, not assume.

**No backward compatibility with older patch versions.** `apply_patch.cmake` refuses any HiGHS tree whose `mip-heuristics patch version` marker is not the current `PATCH_VERSION`, and does not attempt an in-place upgrade — no retired-identifier list, no rewriting an older option layout. **Bump `PATCH_VERSION` on any change to inserted text and clean-rebuild; that is the whole contract.** The clean rebuild is `rm -rf build/_deps/highs-src build/_deps/highs-subbuild build/CMakeCache.txt` before re-configuring — an existing tree was patched by the *old* script, so a modified one either declines to run or appends its new text to an old layout, and the failure then surfaces somewhere unrelated. CI's dependency cache key includes the patch script for the same reason. The marker lives in `HighsOptions.h`, so it speaks only for that file — the surviving probes are the ones for markerless files: `HighsMipSolver.cpp`, whose `heuristics::run_presolve` / `fpr_lp::run` idempotency sentinels are present in every layout the call sites have ever had, and `HighsCliqueTable.h`, whose two const clique-list accessors are likewise markerless. Retiring an option that appeared in an inserted *call site* means updating that file's probe to name it; retiring one that only appeared in `HighsOptions.h` means nothing but the version bump. The same stance applies to the harness: results trees must use the `<config>/seed<N>/` layout, and config names have no aliases.

**Bumping the HiGHS tag**: HiGHS renames `advanced` options across minor versions with no deprecation shim (`pdlp_scaling` → `pdlp_scaling_mode` and `pdlp_e_restart_method` → `pdlp_cupdlpc_restart_method` at v1.14.0). Every `Highs` instance we build sets `output_flag=false`, so a rejected `setOptionValue` is completely silent — it reports failure only through the return status. After a bump, grep for `setOptionValue` and check each name against `_deps/highs-src/highs/lp_data/HighsOptions.h`, and prefer routing writes through a status-checking helper (`set_option_or_die` in `contested_pdlp.cpp`). Verifying that an option *exists* is not enough: check that the code path you're on actually reads it (e.g. `pdlp_scaling_mode` is consumed only by HiPDLP, never by cuPDLP-C).

**Heuristic entry points** — each has a standalone `run()` that HiGHS calls during presolve.

### `fpr` — Fix, Propagate, and Repair

DFS tree search that fixes integers, propagates bounds, repairs the *partial* assignment at every node the fixing or propagation refutes, backtracks on infeasibility, and finally runs WalkSAT/RepairSearch on the leaf.

`fpr_core.cpp` exposes two APIs: the one-shot `fpr_attempt` (scylla / fpr_lp / one-shot tests) and the `fpr_attempt_begin` / `fpr_attempt_step` / `fpr_attempt_finish` lifecycle that lets `FprWorker` pause an in-flight DFS at the per-call budget gate and resume it, with state in `FprAttemptState` + `FprScratch`. Multi-attempt looping inside `run_attempt` lets fast workers fill the slice with new attempts, rotated through `kInitialFprConfigs` per `(worker_idx + attempt_idx)`.

Sub-algorithms: `prop_engine` (bound propagation, forward propagate plus a domain PQ for dynamic-var strategies — `repair_search` requires `e_pq_mark` threading on `RepairSearchNode` to keep the PQ consistent across its secondary backtracks), `walksat`, `repair_search`, `repair_walk`, `fpr_strategies`.

**Propagation results.** `PropEngine::propagate` returns a `PropResult` four-state, not a `bool`: a per-call matrix-access budget (`kPropagateBudgetPerNnz * nnz`) can exhaust before the worklist drains, and the fixpoint also polls the wall clock every `kPropagateDeadlinePollWork` counted units. `kBudgetExhausted` and `kDeadlineExpired` are truncated-but-sound fixpoints, not verdicts: **every caller prunes only on `kInfeasible`**. The two truncations are **not aliases** — budget exhaustion means "this got expensive, carry on", expiry means "the solve is over" — so each caller decides what expiry means *there*: the DFS in `fpr_attempt_step` breaks out of the node loop at once, pushing the node back so the paused stack matches a pre-node deadline break, while `sync_changes` and `apply_branch_to_r` deliberately do **not** signal it outward, because their `bool` can only say "prune" and the RepairSearch loop already polls the same deadline once per node.

The engine takes its `Deadline` through `set_deadline`, not its constructor, and **both arming sites (`acquire_engine`, `repair_search` for E and R) must call it on the *reuse* path as well as on construction**, since both cache an engine across attempts. A null `Deadline` sets the cadence counter to `SIZE_MAX`, so an un-armed engine reads no clock at all.

**Repair runs in the tree, on the partial assignment** (`src/repair_walk.{h,cpp}`, Fig. 1 lines 7-8, at *every* node whose processing left the problem infeasible). Four load-bearing properties:

1. **Violation is the activity range, not a solution vector.** A row is violated when the interval `[m_i, M_i]` its current domain admits is disjoint from the row's bounds — no completion satisfies it — and the violation is the distance between them. Those are the activities propagation maintains, so `fpr_attempt_begin` calls `E.init_activities()` for every `mode_repairs` mode, not only `kLoosedyn` (arming them moves no value selection: `choose_value` reads activities on the `kLoosedyn` branch alone). The same measure is what makes `Apply(fixing, P)` able to refute a node (Fig. 1 line 4), via `any_violated_row_in_column` — without it `dive`, where propagation never runs, could not repair at all, since `PropEngine::fix` fails only on the column's own domain. It also covers propagating modes, where `propagate` skips a row with no unfixed columns. Only the fixed column's rows are scanned, and the check is gated on `do_repair`. **Deliberate deviation**: damage and the best-state comparison sum violation *magnitudes*, not counts — the paper says both; recorded in `docs/PARAMETERS.md` beside `repair_noise`.
2. **A move is a *shift*, and what shifts is the node's domain.** Column `j`'s current interval translates by `s`, keeping its width, through `PropEngine::shift_domain` — a third operation beside `fix()` (refine within the current domain) and `refix()` (override with a singleton). **Enlargement is not a legal repair move**, so a shift is bounded by how far the interval can slide inside the column's *structural* bounds, and a column with an infinite endpoint cannot shift. A fixed column's interval is its `val`, not `[lb, ub]`, because `fix()` leaves those wide. Scoring needs no engine call: translating `j`'s interval by `s` translates both activity endpoints of every row containing `j` by `a * s`.
3. **Every change goes through `E`, so its undo stacks are the snapshot.** The soft restart (back to the best state every `kSoftRestartPeriod` shifts) and the end-of-walk restore are a `backtrack_to` on a four-integer mark; the DFS's backtrack unwinds a repair with its node, and a `step` paused at the budget gate resumes with the repair committed. The tabu list of the last `kTabuLength` shifts survives a soft restart (the paper does not say either way). **Do not "optimize" the restart into an incremental violated-set repair** — an earlier revision did, provably equivalently, and no test could reach it, because the end-of-walk restore masks every observable difference a soft restart makes.
4. **The trigger is `PropResult::kInfeasible` and nothing else.** Its effort valve is **internal** (`kRepairWalkBudgetPerNnz`) rather than a caller argument, because neither number a caller could pass bounds `E.effort()`: the per-call DFS slice is already spent by the time propagation refuted the node, and `FprConfig::max_effort` does not bound the counter. A caller cap turns every repair past the crossing into a no-op that still pays its entry scan — on the long attempt on the hard model, the case repair exists for.

**Phase 3 (leaf-time repair) takes no caller cap either**, for the same reason: `repair_search` is governed by `cfg.repair_iterations` (its propagation fixpoints already answer to `kPropagateBudgetPerNnz`) and `walksat_repair` by `cfg.walksat_iterations` plus `kWalkSatBudgetPerNnz`, which gates the *delta* the call charges because its `effort` parameter is a caller's running total. `FprConfig::max_effort` survives only because the one-shot `fpr_attempt` wrapper reads it as its single DFS gate; under the lifecycle API `run_attempt` leaves it at `SIZE_MAX`. **The scope of both is wider than FPR**: every `mode_repairs` leaf walk — FPR, the two `mode_repairs` Scylla chains (`kFprConfigs[2]` `kDive`, `[3]` `kDfsrep`) and the six `mode_repairs` `fpr_lp` arms of ten (`ZerocoreDive`, `ZerocoreDiveprop`, `ZerolpDiveprop`, `Cliques2Diveprop`, `LpDive`, `LpDiveprop`).

**Cost to know**: a refuted node costs one O(`nrow`) scan (nothing upstream maintains a violated-row set; within the walk it is incremental), and a soft restart pays it again. It is charged to `E.effort()`, so a fixed effort budget buys fewer DFS nodes than a no-repair build would.

**Fig. 1 does not prune an infeasible node in a non-backtracking mode**: lines 9-10 backtrack only `if backtrackOnInfeas` and line 11 branches regardless, so `dive`/`diveprop` carry an unrepaired node to the bottom. **At the bottom they set `found_complete` even when the leaf is infeasible** — Fig. 1 ends at line 16, and Phase 2.5's fill plus the leaf-time `walksat_repair`/`greedy_1opt` are a post-process whose precondition is "a leaf with every integer fixed", never "Fig. 1's `infeas` was false".

**There is one verdict site.** `infeas` feeds the repair call and the backtrack decision and nothing else; what is *returned* is decided solely by `fpr_attempt_finish`'s point re-check over every row. That is what makes `any_violated_row_in_column`'s one-column scan sound — a correct definition of `Apply`'s verdict, an incorrect one of "the problem is infeasible". `infeas` is non-global for two further reasons the same re-check covers: Phase 1's batch fixings bypass `Apply`, and a repair's collateral damage on rows no later column touches is never re-reported. The leaf-time walk is a genuine second chance, not a duplicate: it scores a *point* where the in-tree walk scores activity ranges, from its own RNG stream.

`kRepairSearch` is deliberately **not** in the tree (`mode_repairs` excludes it): moving it in needs `repair_search` to work on a partial assignment, which is open.

**A failed attempt still hands back its point.** Every failure return of `fpr_attempt_finish` carries a `solution` of length `ncol` with every integer column integral and inside `[col_lb, col_ub]`, while `found_feasible` stays false — Sect. 2.3's "always produces an integer-feasible, but not necessarily LP-feasible, solution". So **Phase 2.5's fill runs on every path**, and the `!found_complete` path is charged the fill plus the `ar_index.size()` row rebuild. Phase 2.5 does **not** buy Phase 3: its precondition is still `found_complete`. `HeuristicResult::infeasible_point` is the factory and leaves `objective` at infinity — **no caller may read it**. `found_feasible` still gates every `SolutionSink::offer` site. On the two Phase 3 paths the point is `scratch.solution` **as Phase 3 left it**, not the pre-repair leaf. Two consequences: the fill writes no counter, so **it is wall time no effort gate can see**; and the LP-reference arms draw RNG inside it (`val_lp_based`), where `kBadobj`/`kLoosedyn` draw nothing.

**The leaf-time repair takes the global bounds, and that is correct**: Phase 2.5 has produced a complete assignment, so every column's effective domain is the singleton at its value and the paper's rule for a value shift is the global-bound clip verbatim. "Against the node's current domain, not the global bounds" is about the *in-tree* call. A test asserting only on the returned `HeuristicResult` cannot see this, which is why `tests/test_repair_walk.cpp` asserts on the engine's per-column state *between* the dive and Phase 3.

**RepairSearch** (Fig. 5, Sect. 5.1):

- `sync_changes` (line 13) re-fixes an already-fixed column when R's domain rules it out — the binary-swap mechanism RepairSearch exists for — and fixes a disjoint domain to R's nearer endpoint, via `PropEngine::refix`: a `fix()` validating against *structural* bounds, since both cases target a value outside the current domain by construction.
- **The node loop is a DFS with a gated jump, not a best-first search.** Lines 18-19 backtrack to the best open node only once `progress_threshold` consecutive nodes have failed to improve the best total violation. **The jump runs after the children are pushed**, which is not the figure's line order and is deliberate: `Q` is a LIFO stack, so a promotion made where lines 18-19 sit is buried under the children and resurfaces only once their subtree is exhausted — the very "inability to escape a wrong subtree" the jump exists for. A node reaching neither push never jumps.
- **A jump discards the open nodes beneath it, and must.** Each node restores its parent state by replaying an undo trail down to seven marks, sound only while the marks along `Q` are non-decreasing front-to-back so a pop always unwinds *downward*. `backtrack_best_open` (declared in `repair_search.h`, unit-tested directly, because a whole-search outcome cannot separate "dropped the subtree" from "permuted it to the back") drops every open node after the promoted one whose marks are strictly deeper in **any** of the seven components, keeps the ones whose marks *equal* it (the alt/pref pair pushed at the same parent state, sharing its trail prefix), and only then swaps it to the back. That is exactly the completeness Sect. 5.1 says the jump gives up; a permutation keeping the deeper nodes would cost no completeness at all, which is the tell. **Clamping the backtracks to the live stack size instead hides the symptom, not the bug** — after a jump the trail beneath a deeper node's mark has been *rewritten*, so even a non-growing restore reinstates an unrelated state.
- `RepairSearchStats::mark_overshoots` is checked at the pop site over all seven marks and **must stay zero**: it is the Release-mode observable of that invariant, since the tests build `-DNDEBUG`. `nodes_abandoned_by_jump` counts what a jump gives up.
- `progress_threshold` is a parameter defaulted to `kRepairProgressThreshold` (`repair_search.h`; no option behind it). `fpr_core.cpp` names no value, so the production value lives in one place; `tests/test_repair_search.cpp` runs one model at both ends of the axis and pins the defaulted call against an explicitly-valued one.
- **The post-loop restore is not Fig. 5 line 27**, and its comment says so and says it is a choice: line 27 is implementable verbatim here *because* of the mark-ordering invariant. What is restored instead is the best `(solution, lhs_cache)` snapshot line 17 took — the best node *visited*, which is at least as good as the best still *open* under line 17's own measure. Nothing is restored when `repair_track_best` is false. `RepairSearchStats` is the seam the tests read; production passes `nullptr`.
- **`MoveToDisjunction` branches on the shifted interval, and each disjunction is a point split.** With `[a, b]` = **D translated by the move's shift** and R's domain `[c, d]`, `l = a - c`, `r = d - b`: if `l <= r` impose `x_j <= b \/ x_j >= b`, else `x_j <= a \/ x_j >= a`.
  - Building `[a, b]` from D itself instead makes both children re-impose a bound R already holds, leaves `sync_changes` nothing to transfer, and moves nothing on a general-integer column. What shifts is the *interval*, so it keeps D's width; a fixed column's D is the singleton at its `val`.
  - **Both sides naming the same endpoint is not a printing error.** `x_j <= v \/ x_j >= v` covers the line and leaves the shifted interval intact in exactly one child; choosing which endpoint to split at is the only thing the two gaps are for. The "obvious typo" fix — the overlapping pair `x <= b \/ x >= a` — is a cover **with a hole**: `(a, b)` is in neither child, and the move value sits exactly there whenever the point is interior to D.
  - Which child is *preferred* is not in the text; we take the one holding `[a, b]`, by analogy with the binary case.
  - **The containment is a deviation, not a fact**: `walksat_select_move` clips a shift to structural bounds rather than to R's domain, so `[a, b]` can leave `[c, d]` and is clipped back in. Reachable only at zero width with a point drifted off a fixed column's value; at positive width `width(D) <= width(Dr)` forces the selected endpoint to stay inside.
  - Downstream, the clamp turning a bound branch into a point move reads the interval **E holds**, not `[lb, ub]`, since `sync_changes`' intersection case commits through `PropEngine::fix`, which leaves the bounds wide.
  - `move_to_disjunction` is declared in `repair_search.h` and unit-tested directly, for the reason `sync_changes` is: a whole-search outcome cannot separate two split points, because the point ends up clamped to whatever propagation implies. `RepairSearchStats::bound_branch_moves` counts nodes where a bound branch moved the point.

**`FprConfig::strategy` is always required**: `choose_fix_value` has one path, the paper's variable ranking + value selection (`fpr_strategies`'s `choose_value`), which reads `FprConfig::lp_ref` for the LP-based value strategies (`kZerocore`/`kZerolp`/`kCore`/`kLp`) — the single reference-point mechanism into fix-and-propagate.

`fpr_attempt`/`fpr_attempt_begin` carry **no seed input**, and adding one back would be inert: every write into the engine's solution array is overwritten by `fix()`/propagation auto-fix or by the Phase 2.5 fill before anything reads it.
### `fpr_lp` — LP-dependent FPR (paper Classes 2–3)

Uses the root LP solution. Called during the B&B dive (after RENS/RINS), not presolve. Draws from the **same LP-iteration budget as RENS/RINS** (`mip_heuristic_effort` envelope) and charges its work back.

Gated by `mip_heuristic_fpr_lp_effort > 0`, and by nothing else. **Where that gate returns from is the whole of it** — above every read and write of `heuristic_lp_iterations` / `total_lp_iterations`, which feed `moreHeuristicsAllowed()` and therefore decide whether RENS and RINS run, so a disabled `fpr_lp` leaves those two exactly as they were; that is what makes an `fpr_lp` ablation an ablation of `fpr_lp`. `tests/test_fpr_lp.cpp` pins that no presolve-only selection dispatches it. It skips entirely while `parallelLockActive()` — multi-worker B&B under `parallel=on` — because those counters are shared and it has no worker-local flush path.

It runs arm-aligned parallel workers (`w % kNumLpArms`): each of `num_threads` workers is bound to an LP arm from the curated Class 2/3a/3b list, excess workers wrapping the arm list with distinct seeds. Each arm is one `LpArmInfo` record in `kLpArmTable` (`src/fpr_lp.cpp`) carrying its `(strategy, mode)` pair *and* the reference-vector class (`LpRefClass`) its strategy is defined against — analytic center (Class 2), zero-obj vertex (Class 3a), or full-obj LP (Class 3b) — so the arm-to-class assignment is derived from that one record rather than kept in sync across parallel per-class arrays that can silently disagree. `fpr_lp::lp_arm_table()` is what `tests/test_fpr_lp.cpp` asserts on ("every LP arm's reference class matches what its strategy needs").

**That table-level test is only half the binding.** `build_setup` still has to turn a `ref_class` into a pointer, through **`select_ref` — a small pure function, not a switch inlined at the call site, with no `default` case and no pointer pre-assigned before the switch** — with its own test exercising every enumerator directly (`"fpr_lp: select_ref returns the pointer its LpRefClass names"`). `-Werror=switch` on every library and test target of ours turns an unhandled enumerator into a compile error, for this switch and every other one in our own code.

**`LpArmInfo`/`LpRefClass`/`lp_arm_table()`/`select_ref` live in `src/fpr_lp_arms.h`, not `fpr_lp.h`**: the patch inserts `#include "fpr_lp.h"` straight into HiGHS's own `mip/HighsMipSolver.cpp`, compiled at HiGHS's own `CMAKE_CXX_STANDARD 11` (not this project's C++23), so `fpr_lp.h` stays a bare forward declaration of `HighsMipSolver` and **nothing it includes may drag in `fpr_strategies.h` / `heuristic_common.h`** — both use C++17 `inline constexpr` and C++14 multi-statement `constexpr`, which fail to compile under `-std=c++11`.

Its per-dispatch `build_setup` — CSC transpose, two reference LP solves, one `compute_var_order` per arm — is sequential on the dispatching thread and sized by nothing, so it is deadline-gated between arms and around each solve, and **a bail owes the envelope**: a setup abandoned after a reference solve has already spent LP iterations that must still be booked. It returns a `SetupResult` (the optional setup, `lp_iterations` spent whether or not one came back, and `deadline_bail`), and `fpr_lp::run` charges through `charge_dive` on exactly one of two disjoint paths — the bail books `effort=0` plus whatever the solves cost and reports `abandoned_setup=1`; the normal path books once at the end. The model-shape and LP-status skips consume nothing and stay silent. **Poll the clock rather than testing the returned LP vector**: the `ac_ptr`/`zv_ptr` fallbacks read an empty vector as "LP failed, use the full-obj solution", which would mask an expiry. Nothing is cached across dives, so no path can charge another's work.

`dive_budget` is a **free function with its own test**, not four lines inlined in `run`, because no assertion on a solve separates "the share scaled the budget" from "the budget happened to land there". It computes `share * min(headroom_units, cap_units)`, with the cap `vanilla_effort_budget(nnz, mip_heuristic_effort)`. **The share multiplies the whole `min`, not the headroom term inside it** — otherwise the per-call cap binds at every share and the option cannot express a budget that never binds, the one thing its `1e6` ceiling exists for. Overdrawing the envelope at a large share is self-correcting rather than a leak: the charge-back depletes the same counters the headroom is computed from, so the next call sees none and skips.

`fpr_lp` has no patience option and keeps `worker_budget >> 2` with its own improvement signal.

### `fj` — Feasibility Jump

HiGHS's own FJ implementation, run on continuous parallel workers — a delegating wrapper, but not a *thin* one: `apply_patch.cmake` corrects two upstream defects in `feasibilityjump.hh`, inherited from the SINTEF reference and present in HiGHS v1.15.1 and on master.

1. **The negative-coefficient jump value.** `JumpMove::updateValue` divides both endpoints of a row's bound interval by the variable's coefficient, which reverses the inequality when the coefficient is negative; without a swap `validRange.first > validRange.second` fires unconditionally and the row is dropped, contributing neither a critical value nor a slope. Paper eq. (5)/(6) give the critical value an explicit negative-coefficient case and Algorithm 1 accumulates the pre-bound slope by that sign, so the fix is one conditional swap placed **before** the integer ceil/floor — after it, `floor` on the true lower endpoint yields a value one below the smallest that satisfies the row. What degrades is the **move — the (value, score) pair — not the scoring rule**: `resetMoves` builds `candidateLhs` from `move.value`, so it scores the move `updateValue` just chose. Damage concentrates on general integers and continuous columns.
2. **The sign of the objective term in the move score.** Sect. 2.6 makes the score a *minimized* sum; the constraint terms are improvement-positive, `selectVariable` takes the maximum, `updateGoodMoves` calls a move good when its score is positive, and both live callers hand `addVar` coefficients already multiplied by the model sense — so upstream's spelling scores an objective-*worsening* move positively. It is negated at **both** sites that spell the term, `resetMoves` (recomputed) and `updateWeights` (applied incrementally on the no-violated-constraint branch): a sign disagreeing between them would drift the scores apart on every weight bump.

Pinned by `tests/test_fj_jump_value.cpp` (which drives `JumpMove` directly as well as the solver, because two cases pin the *slope* half, whose models FeasibilityJump cannot satisfy) and `tests/test_fj_objective_sign.cpp`. The sign test covers `resetMoves` and not `updateWeights`, because the two disagree only by drift. **The patch's post-check asserts on both sites and on the absence of either `+=` spelling; it refuses a half-applied patch and is a spelling check, not a substitute for a test.**

The patch also **drops FJ's per-bump `Reached a local minimum.` log line**, which was ~99.8% of a `log_dev_level=3` run's log volume and made a clock-bound traced FJ dispatch a different heuristic from an untraced one. What remains at level 3 is FJ's periodic table and our own two lines — closer, but still not the same run, which is why `run_benchmark.py` leaves level 3 off behind `--dev-log`. A patched binary's FJ output no longer matches vanilla's at level 3, one of the reasons `off` is an ablation and not a vanilla proxy.

**FJ's per-worker solver construction is unbounded** — `createRowwise` plus `addVar`/`addConstraint` plus `init`'s `resetMoves`, before the first callback can fire — and is deliberately out of scope; a deadline in the callback cannot bound it.

### `local_mip` — weighted local search

MIP neighborhood search, run on continuous parallel workers.

### `scylla` — feasibility pump (Mexi et al. 2023)

Alternates PDLP approximate LP solves with FPR rounding, progressive objective blending, and cycling perturbation. Runs N independent pump chains sharing a single `ContestedPdlp` instance so only one PDLP solve is in flight at a time. Workers that can't grab the PDLP mutex fall back to rounding against the most-recent *stale* snapshot so N-1 chains stay productive during a peer's solve, bounded by `kMaxStaleRounds` per worker before forcing a blocking solve.

Each chain owns its own warm-start, α_K decay, cycle history, RNG, and static FPR rounding strategy (`kFprConfigs[w % N]`). **Every chain's value strategy is `ValStrategy::kLp`**, so each chain's rounding reads the pump's PDLP iterate `x_bar` via `FprConfig::lp_ref` (Algorithm 1.1 line 12). Variable strategy, framework mode and RNG stream stay diverse per chain — three distinct variable strategies across the four entries, `kTypecl`/`kLocks`/`kLocks`/`kLR`, the latter two named `kStratLocksLp`/`kStratLRLp` in `fpr_strategies.h` as Scylla-specific, non-Table-3 combinations.

The variable *order* stays `x_bar`-free: precomputed once per dispatch on the dispatching thread (`scylla::precompute_config_var_orders`), because a per-iteration order would reach the live clique table from inside the parallel pump loop.

**Cycling detection is near-dead in the fractional regime, and that is sanctioned rather than a defect.** `val_lp_based` is probabilistic (Sect. 4.2), so away from an integral `x_bar` the same iterate no longer maps to the same `x_hat` and `pump::detect_cycling`'s exact-vector match rarely fires, leaving line 14's perturbation near-dead there; it re-arms near convergence, where `frac < 1e-10` makes the rounding deterministic. The randomized in-tree repair on the two `mode_repairs` chains adds a second source of the same effect. Know this before a cycling investigation starts from scratch.

**A failed rounding still advances the pump.** Lines 14-16 run unconditionally — a feasibility pump is *defined* by being pulled toward the rounded point whether or not it is feasible, and line 13 returns only when it is MIP-feasible — so `detect_cycling`/`perturb`, `record_cycle_entry`, the `alpha_K_` decay, `compute_pump_objective` and `++K_` all run on a failed round; otherwise the chain re-solves a byte-identical LP with a byte-identical `modified_cost` and makes no progress. The only `solution.empty()` guard left is the degenerate `ncol == 0 || nrow == 0` short-circuit. Consequences to know rather than fix: `perturb` draws from `rng_` on failed-rounding cycles, and the `pdlp_stall_count_` retirement a repeated identical LP used to produce mostly disappears. No pool restart is fed into the rounding call.

## Dispatch and parallel infrastructure (`src/`)

- `mode_dispatch` — top-level presolve entry point. Reads `mip_heuristic_*` options and runs the fixed chain via `run_sequential`: FJ → FPR → LocalMIP → Scylla, each with its own effort budget and each on continuous parallel workers. The chain is a `constexpr` four-entry `HeuristicConfig` table (`{name, source_tag, flag, effort, budget_is_per_worker, patience, run}`, `effort` a pointer-to-member naming that heuristic's effort option) and `run_sequential` is a filtered loop over it — **adding or reordering a heuristic is a table edit**. There is one parallel runner. Reproducible runs come from `threads=1` plus a fixed `random_seed`; no new option.
- `heuristic_context.h` — the common runner contract, with no `mip/` include. FJ and LocalMIP expose `DispatchOutcome run(const ProblemView&, const HeuristicBudget&, ExecutionContext&, SolutionSink&)`; FPR and Scylla take the `HighsMipSolver&` first (clique rankings, `ContestedPdlp`), and `kChain` adapts the other two with `without_solver`. `ProblemView` is everything a worker reads: the model (`HighsLp`, for its column-wise matrix only), the objective as `col_cost`/`offset` and the `integrality` the workers use in place of the model's, the row-wise matrix, the CSC transpose, the lock counts, `feastol`/`epsilon`, derived `ncol`/`nrow`/`nnz`, and the incumbent and `isBinary` snapshots. **The view is always a minimisation problem, and no core code reads the model's bounds, cost, offset, sense or integrality**: inside HiGHS the presolved model already is one (`HPresolve` negates a maximisation model before any heuristic runs, presolve on or off), and the core `make_problem` negates a caller's maximisation model into `ProblemStorage`. So the search code has no maximisation branches, and every objective a worker computes, a `SolutionSink` receives or a `SolutionPool` ranks is `offset + col_cost . x` in that form — minus the original objective for a maximisation model. The core `make_problem` returns `std::expected<ProblemView, ProblemError>` and, in one linear pass, mirrors HiGHS's own model assessment (`assessLp`, `assessBounds`, `assessMatrix` in the pinned tree; **look there, not at a guess, when extending it**): what HiGHS refuses with an error is `kMalformed` (sizes that disagree with the dimensions; a matrix not column-wise with them; starts that do not begin at 0, are not monotone or do not cover the arrays; row indices out of range or repeated in a column; an integrality or sense outside its enum; NaN; a non-finite or `infinite_cost`-sized cost or offset; a coefficient at or above `large_matrix_value`; a lower bound at `+infinite_bound` or an upper one at `-infinite_bound`), what it passes with a warning is `kInfeasible` (crossed bounds; also an empty row whose bounds exclude 0), and semi-continuous or semi-integer columns are `kUnsupported` (the workers read integrality as "anything but continuous is an integer"). Into `ProblemStorage` it maps bounds of magnitude `infinite_bound` (1e20) or more to infinity, as HiGHS does, and rounds integer column bounds inward (`ceil(lb - feastol)`, `floor(ub + feastol)`, refused if they then cross), which is why the view carries its own column and row bounds and no core code reads the model's. `tests/test_problem_view.cpp`'s parity case holds the result to the adapter's view of the same model: equal CSR, locks, binary mask and bounds. A model without `integrality_` is all continuous. **Validation lives in `make_problem`, not in `SolutionSink`**: inside HiGHS `trySolution` already checks every submission, and a caller of the core checks at publish time. The presolve chain builds it **once per dispatch** with `make_problem(HighsMipSolver&, CscMatrix&)` in `highs_context.h` and shares it across the chain (`mipdata`'s row-major buffers are frozen by `runSetup()` before dispatch). A caller that owns its model uses `make_problem(const HighsLp&, ProblemStorage&, ...)` instead; see the core/adapter split below.
  - **Workers must read `problem.incumbent`, never `mipdata->incumbent`.** Submission is immediate, so a peer's accepted solution runs `addIncumbent` — whose `incumbent = sol;` rewrites that buffer element-wise and reallocates it on the empty-to-sized transition — while a worker indexes the live vector. Read it *after* the pool, never instead of it: every accepted solution goes through the pool first, so `copy_best` is the thread-safe way to see a peer's find, and a worker rebuilt mid-dispatch (FJ does this on staleness) that skipped the pool would silently lose it.
  - **Anything else a worker reads out of `mipdata` must be frozen by `runSetup()` or snapshotted the same way.** `fpr_lp` builds its own view (`problem_view`) over the CSC its setup built; `IncumbentSink`'s constructor reads the live vector to seed the pool only because it runs on the dispatching thread before any worker starts. `ProblemView::binary` is the second such snapshot: `addIncumbent` also runs `getDomain().propagate()` and `redcostfixing.propagateRootRedcost`, which tighten the root bounds `HighsDomain::isBinary` reads, so workers classify columns from the snapshot — LocalMIP via `WorkerCtx::is_binary`, FPR/Scylla/fpr_lp through the `ProblemView` FPR's search is handed.
  - **The one live `isBinary` read left is `bucket_by_type` in `fpr_var_order.cpp`, reached only through `compute_var_order`, and every `compute_var_order` caller must run on the dispatching thread** — `fpr::precompute_var_orders`, `fpr_lp`'s `build_setup`, `scylla::precompute_config_var_orders` — because `addIncumbent`'s `extractObjCliques` reallocates the clique table concurrently. **Any new caller is bound by the same rule** — which is why FPR's search takes the order precomputed (`FprConfig::precomputed_var_order` is required) rather than computing one itself.
  - `HeuristicBudget` is one heuristic's `total`/`per_worker`/`attempt_cap`/`stale`/`worker_stale` split from `make_budget`, which takes the staleness ceiling as an argument rather than deriving it. `ExecutionContext` carries worker count, base seed, the `Deadline`, the log options and the `terminator` callable; `make_exec` (`highs_context.h`) binds that callable to `terminatorTerminated()`. `fpr_lp` takes only `make_exec`/`make_budget`.
- `solution_sink` / `incumbent_sink` — the only path from a worker to a solution. `SolutionSink` (core) owns the `SolutionPool` and the source tag, returns the offer verdicts and counts acceptances; workers call `sink.offer(obj, sol, ...)` and never name their own tag. Each accepted offer reaches its virtual `on_accept` on the offering thread, outside the pool lock. `IncumbentSink` (adapter) derives from it: it seeds the pool from the incumbent, overrides `on_accept` to call HiGHS's non-thread-safe `trySolution` under its mutex and emit `[HeurSol]`, and owns the dispatch boundary. `run_sequential` re-tags via `set_source` between heuristics (legal only there — every parallel region has joined). Its atomic `accepted()` counter moving across one dispatch is the `found` field of that heuristic's `[Heur]` line, since a worker's return value is its effort and nothing else.
- `effort_ledger` — the only place that writes `heuristic_effort_used` or emits the `[Sequential]` / `[Heur]` lines, anywhere in the build. `charge_presolve` for the chain; `charge_dive` for `fpr_lp`, which additionally depletes the RENS/RINS LP-iteration envelope. `EffortLedger::now_s()` is the solver's own clock (`HighsMipSolver::timer_`), not a raw `steady_clock`, so `[Heur] start_s/end_s` share an origin with HiGHS's display-line time column. **Nothing else in `src/` writes an upstream `HighsMipSolverData` counter.**
- `worker_base.h` — `AttemptResult` (one attempt's effort + improvement flag) and `WorkerBudgetState` (per-worker effort / staleness / budget bookkeeping, embedded by composition into all four workers — `FprWorker` arms only the staleness half, leaving `total_budget` at SIZE_MAX because the whole-dispatch ceiling belongs to the runner).
- `opportunistic_runner.h` — the generic continuous parallel loop every heuristic runs on, and `run_on_caller_thread`, one slot of the same loop on a caller's thread for `run_until_stopped`.
- `scylla_worker` / `pump_common.h` — Scylla worker class and shared feasibility-pump primitives.
- `fj_worker` / `fpr_worker` — the FJ and FPR worker classes. `FprWorker` is declared inline in `src/fpr.cpp`; there is no `fpr_worker.*` file.

### `contested_pdlp`

Mutex-guarded `Highs` PDLP wrapper shared by all Scylla workers. One-shot `solve(modified_cost, warm_start, epsilon)` holds the mutex for the full `changeColsCost → setSolution → run → getSolution` path, guaranteeing at most one PDLP solve is in flight (critical for cuPDLP GPU state); the in-flight counter is debug-asserted == 1 inside the critical section. `try_solve_or_snapshot(...)` is `try_lock` + fresh solve on success, or a lock-free `std::atomic<std::shared_ptr<const Snapshot>>` read of the most-recent completed solve on contention.

- **The `epsilon` argument is the pump's single stopping error and must reach all three parameters cuPDLP-C's termination check reads** — `D_PRIMAL_TOL`, `D_DUAL_TOL`, `D_GAP_TOL` — because cuPDLP-C terminates on their conjunction and relaxing a subset relaxes nothing.
- **It gets there through one write to `kkt_tolerance`, not three writes to the tolerance options, and that is not stylistic.** `primal_feasibility_tolerance` and `dual_feasibility_tolerance` are not private to the PDLP solve: `HPresolve` reads both verbatim in ~100 places (`weaklyDominatedCol` fixes a column whenever `direction * dualBound >= -dual_feasibility_tolerance`, and the pump's modified costs are O(0.1–1)), so writing them presolves a *different LP* rather than solving the same one loosely. `kkt_tolerance` is resolved into feasibility thresholds only as *function-local* variables in `HighsSolution.cpp`'s KKT checks. The route also keeps HiGHS's own KKT accounting consistent with the solve, since both read the same constant. Domain `[kMinimumKktTolerance = 1e-10, kHighsInf]`, so no schedule value is clamped.
- Its cost is that it leans on an upstream "if changed from its default" branch — the cross-version fragility the HiGHS-bump paragraph warns about. So `tests/test_contested_pdlp.cpp` pins the **effect** (a looser epsilon takes strictly fewer PDLP iterations), not the option name, with a **third arm** requiring the loose epsilon to also beat an untouched-`kkt_tolerance` solve, so a bump re-conditioning the override to fire only *below* the default cannot strand the loose end silently.
- `SolveResult::model_status` is public and stays epsilon-dependent in principle; `absorb_fresh_solve` retires on `kError`/`kInfeasible` alone, so a future caller testing `== kOptimal` should read this first.
- **The wrapped instance never presolves**: the constructor writes `presolve` = `off` through `set_option_or_die`, and the reason is the pump's warm start, not presolve's cost. `optimizeModel` cannot take its presolve-skip branch under `solver=pdlp`, and on `kReduced` HiGHS calls `solveLp(reduced_lp, ...)` with the **full-model** solution object while `solveLpCupdlp` resizes it to the *reduced* LP's dimensions with `value_valid`/`dual_valid` unchanged — so `PDHG_PreSolve` read a truncated prefix of our warm start, landing the previous iterate on the wrong columns and rows. `presolve=off` is well defined here (`runPresolve` returns `kNotPresolved`, no postsolve, `getSolution()` in the full column space, which is what `absorb_fresh_solve` stores and `ScyllaWorker` asserts on). **Consequence**: a `pdlp_iters == 0` return is *reachable*, so `pump::kMaxPdlpStalls` is a live retirement path — three in a row should stay hard, since the modified cost changes every round, and `tests/test_deadline.cpp`'s "a clock-bound Scylla dispatch spends its whole limit" is the standing check. An instance that does retire early is a separate issue about the stall rule, **not a reason to put presolve back**. The surviving design option (presolve once in the wrapper and keep the pump in the reduced space, mapping the iterate ourselves) is recorded in `docs/PARAMETERS.md`.
- **The solve's time limit is not an argument**: the wrapper owns the `Deadline` and reads what is left of it *inside* the lock, because a caller computes a value and then blocks for the length of a peer's whole solve. A solve entered past the deadline returns an empty `SolveResult`, whose `kError` default retires the chain.
- **`solve_locked` calls `highs_.zeroAllClocks()` inside the lock and before the `time_limit` write**, because that limit has two consumers with different clock origins: cuPDLP-C charges from entry to `PDHG_Solve` (this solve), but `Highs::runPresolve` compares `options_.time_limit` against the *wrapped instance's* clock, which accumulates across every solve of the dispatch. Without the zeroing, a shrinking remaining time meets a growing accumulated one about halfway through the dispatch and every later solve returns `Time limit reached` with 0 PDLP iterations, retiring the chain. **Do not "fix" this by widening the limit handed to the sub-solver** — that repairs the ratio while leaving presolve budgeting against a growing origin *and* over-granting `D_TIME_LIM`; the ratio test in `tests/test_deadline.cpp` is paired with a cause test reading the accumulated time back through `run_time_for_test()`. `CupdlpWrapper.cpp`'s `getUserParamsFromOptions` computes a remaining-time adjustment and then assigns the *unadjusted* `options.time_limit` to `floatParam[D_TIME_LIM]`; a bump reviving that dead adjustment changes what the per-solve limit means and must re-derive this.
- Test hooks — `tolerances_for_test()` (reads `kkt_tolerance` back plus the three options that must **stay at their defaults**), `run_time_for_test()`, `presolve_status_for_test()` — take no lock and are **dispatching-thread-only, with no solve in flight**.

## Shared utilities (`src/`)

- `heuristic_common.h` — `HeuristicResult`, `CscMatrix`, row violation, clamping, effort-budget and patience sizing. Not the deadline: that is `ExecutionContext` in `heuristic_context.h`.
- `clique_cover` — the paper's Sect. 4.1 clique-cover constructions, as pure functions over a clique-table snapshot. `build_clique_cover` is the five-step greedy `typecl` uses and, by the paper's own sentence, `cliques` shares: equality cliques first (only ones disjoint from what is already in the cover, in clique-table order), then a largest-covering-clique assignment over the rest with one local-adjustment pass and a size-descending sort, members within a group in clique order, uncovered binaries appended in formulation order. `cliques2_order` is Fig. 3, a *different* cover — one pass over every clique, no partition step, driven by the zero-obj vertex — and it **skips an entire clique** whose literal is already fixed true. Both replace `HighsCliqueTable::cliquePartition`, which has no equality pass, no disjointness test, no size sort, and reorders within a clique; the paper's construction needs the table's equality flag and stored literal order, so the patch adds two const accessors (`getCliques()` / `getCliqueEntries()`). Being a table read, it is bound by the dispatching-thread rule.
  - **The per-clique vector allocations are hoisted and must stay that way**: `keyed` in `fpr_var_order.cpp` is declared outside the per-group loop and cleared inside it; `picked` / `selected` in `clique_cover.cpp` are function-scope.
  - **Two deliberate interpretations.** The Fig. 2 sampling key is the standard Efraimidis-Spirakis `log(Rand(0,1))/w_j` sorted descending, not the figure's `log(Rand(0,1)/w_j)` ascending — recorded as an ambiguity above `rank_cliques`; **do not "fix" that comment back into a claim about the figure.** The **size-sort direction** is the second: the paper names none, and descending is our reading.
  - There is deliberately **no minimum group size** — the paper's greedy has none, a threshold would be a deviation rather than a gap being filled, and an earlier `kMinCliqueGroupSize = 2` was measurably inert.
  - The path only **reads** the clique table where `cliquePartition` mutated it, so this is a net thread-safety improvement, and dropping the shuffle stops perturbing the table's RNG stream (an intentional behaviour change). Note `build_bare_mipsolver` turns HiGHS presolve off, which leaves the clique table **empty** (it is `HPresolve` that extracts cliques), so the tests drive a real `HighsCliqueTable` through the public `doAddClique`; no bundled instance yields an equality clique after presolve, so step 1 is synthetic-only coverage.
- `solution_pool` — thread-safe top-K solution pool with crossover restarts. It is a **restart reservoir, not an incumbent store**: HiGHS's `addIncumbent` takes a solution only when it strictly improves the upper bound, so the pool's looser admission never loosens what the solve reports. That looseness is `kDiversityObjTolerance` — a full pool also admits a solution within 10% of the best when it is at least `kDiversityMinHammingFrac` from *every* entry — and it exists so crossover has diverse parents. The diversity path evicts the admitted offer's nearest neighbour **other than the best entry, which it may never evict**: it runs only on an offer the pool already considers dominated, so evicting the best would degrade `copy_best` and the crossover's better parent until the pool refilled. Diversity is still measured against the best; only eviction skips it. **Entries are `shared_ptr<const std::vector<double>>` and never written once inserted** (#180), so the lock covers decisions and pointer moves only: the diversity scan runs outside it on a pointer snapshot and is re-decided if `generation_` moved meanwhile (rescanning only entries it has not seen, so each offer is decided as one hold of the lock would decide it), and `copy_best` / `get_restart` / `sorted_entries` copy or cross over outside it — `get_restart` still makes every entry-picking RNG draw under the lock, in the old order. `entry_refs` hands out the pointers themselves, valid after eviction. The `const&` `try_add` copies the offer into a `shared_ptr` before the lock, offered or not. A non-finite objective or point is refused before anything else (#174): a NaN objective ranks nowhere sensible and would reach every later comparison. The scan reads the integer columns' ascending index list (`IntegerColumns`, beside the flag array the crossovers test), rounds through an inlined exact `std::round` (`round_half_away`), and stops at the first entry the offer is too close to, since that entry refuses it whatever the rest measure; `tests/test_solution_pool.cpp` holds its every verdict to a full `std::round` scan. `mip_heuristics_pool_tsan_tests` runs the pool's tests under ThreadSanitizer.
