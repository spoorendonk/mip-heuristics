Thread count is load-bearing, not decoration: throughput ratios in this project do not cancel across worker counts — the same binary on the same instances gives `local_mip:scylla = 4.68` at 16 workers and `2.81` at 6. The `threads` option says what was asked for, which is deliberately nothing; the observed row says what HiGHS ran at, read from each log's `Thread count N (of M threads)` line. More than one value there means the tree mixes machines.

Instrumentation state is equally load-bearing. `log_dev_level=3` costs 97-750x the log volume and 1.1-4.4x the wall time, concentrated in the FeasibilityJump phase, so an attribution run and a headline-timing run are different runs and their timings are not comparable.
