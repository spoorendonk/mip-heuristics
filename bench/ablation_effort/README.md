# Ablation A — effort and patience, measured per heuristic

The four presolve heuristics' effort budgets and patience thresholds, measured
with each heuristic running **alone**. Everything in this directory is
regenerated by one command from a probe results tree:

```bash
bench/run_presolve_probe.sh preprobe next 12   # the measurement (~8 h, 233 instances x 4 arms)
bench/derive_from_probe.sh                     # every file here
```

Same tree plus same seed reproduces every file byte for byte; none carries a
timestamp.

**What this stage produces is a search centre, not a shipped default.** The
vector below is what `bench/ablation_search/` (Ablation B) centres its domains
on; the shipped defaults are B's selection. What this stage *does* hand
downstream unchanged is the informative set and the 90-instance tuning set.

## The measurement

Taken on a 16-core / 32-thread machine (HiGHS defaults its worker count to half
the hardware threads, so **16 workers**), CPU build.

Each heuristic ran **alone** — its own effort option positive and the other
three at `0` — presolve-only, over all 233 `mipfeas` instances at one seed,
capped at 30 s, with its effort option at the `1e6` ceiling and its patience at
`0`. Those two settings are the whole design:

* effort `1e6` means the budget **cannot bind** on any model;
* patience `0` means **no gate at all** (not "give up immediately");

so **the wall clock is the single stopping rule, identical for every heuristic
on every instance**. That is checked rather than assumed:

```
probe check    932/932 presolve-only, 932/932 patched
budget check   881/881 traced dispatch(es) clock-bound, 0 budget-bound
               0 .log.err, 0 TIMEOUT kills, 0 abandoned_setup
```

Running each **alone** matters: `run_sequential` is sequential, so at an
unbindable budget the first heuristic takes the entire cap and a chained probe
would report the other three as having produced nothing. Membership in the
informative set below is the *union* over the four singles, which dominates
every subset — a heuristic that cracks an instance inside some mix also cracks
it running alone, earlier and with the whole cap to itself.

Cost: 932 runs in 8.0 h.

## What was derived, and how

| heuristic | effort | patience | scope | knee rests on |
|---|---|---|---|---|
| fj | **0.5665** | **0.1416** | per worker | 144 finished |
| fpr | **12.2559** | **3.0640** | per dispatch | 139 finished |
| local_mip | **13.9607** | **3.4902** | per dispatch | 158 finished |
| scylla | **3.0680** | **0.7670** | per dispatch | 130 finished |

### effort = the p50 of the yield knee

Every `[HeurSol]` line stamps an accepted solution with the charged effort at
which it arrived, so **one clock-bound dispatch is a whole cumulative-yield
curve**. That dispatch's *knee* is the effort at its **last incumbent
improvement** — spend beyond it bought nothing on that instance. The value is
the **median knee over the dispatches that finished improving**.

Three choices, each with a reason:

* a **barren** dispatch (no improvement at all) has no knee. It is excluded,
  because it poses a *cost* question — answered by patience — not a budget one.
* a dispatch **still improving** when the cap fired is **right-censored**: its
  true knee is larger than what it was seen to spend, so counting it as if the
  cap were its knee would bias the estimate upward.
* the **median**, not a tail quantile. The p90 is driven by the still-improving
  dispatches, so it measures the cap rather than the heuristic.

The report also prints an upper end — the same quantile with the censored
dispatches carried as censored — which brackets the answer:

```
fj          0.5665 ..  6.6125
fpr        12.2559 .. 93.7124
local_mip  13.9607 .. 50.8226
scylla      3.0680 .. 17.8144
```

Read each value as *a sensible centre to search around*, which is exactly what
Ablation B uses it for.

### patience = min(p95 of the inter-improvement gaps, effort / 4)

The **p95 is a retention claim**: give up after this much improvement-free
effort and at most 5% of the improvements that would ever arrive are cut off.
The **clamp is a cost claim**: a barren dispatch spends *exactly* the patience
and nothing else, and 29–40% of dispatches are barren, so the threshold has to
stay well under the ceiling. The divisor is `kPatienceCeilingDivisor` = 4.

**The clamp binds on all four.** The raw p95 waits are:

| heuristic | measured p95 wait | ceiling (effort/4) | derived |
|---|---|---|---|
| fj | 2.46 | 0.141625 | **0.1416** |
| fpr | 5649.87 | 3.063975 | **3.0640** |
| local_mip | 4.93 | 3.490175 | **3.4902** |
| scylla | 18.96 | 0.767 | **0.7670** |

So every derived patience is `0.25 x` the effort beside it, and the honest
reading is *"for three of these four, the measurement says wait longer than
your entire budget"*. LocalMIP is the only one whose measured wait is within
striking distance of its own ceiling fraction.

**The divisor is upstream's, and is deliberately not tuned.** HiGHS's own
FeasibilityJump pairs `kMaxTotalEffort = nnz << 10` with
`kMaxEffortSinceLastImprovement = nnz << 8`
(`highs/mip/HighsFeasibilityJump.cpp`), a ratio of exactly 1/4 — and the
`nnz << 10` base our effort options are denominated in is that same upstream
constant. `kPatienceCeilingDivisor = 4` adopts the reference implementation's
shape rather than inventing one.

Three reasons it stays fixed rather than becoming a searched parameter:

* **Provenance.** Deviating from the reference ratio would need evidence;
  keeping it does not.
* **It binds nothing that was not already close.** All four derived values sit
  at 21–28% of their ceilings before the clamp and at exactly 25% after. The
  constant bounds future values.
* **Ablation B's null covers the reachable range.** Within `[0, effort/4]` the
  searches placed patience everywhere from 0 (gate off) up to the clamp, and
  n=48 could not separate any of it at 20.6% resolution. A landscape that flat
  *inside* the range gives no reason to expect its edge to matter — and the
  divisor is `constexpr`, so testing it would cost a rebuild per point rather
  than a sweep.

Note the direction of that finding. The p95 is a *retention* statement and the
clamp is a *cost* statement, and on three of four heuristics they disagree by
orders of magnitude — FPR's measured wait is 5650 against a ceiling of 3.06,
a factor of 1800. So on those three the derived value is **not** the
measurement: it is the cost bound, and the measurement only tells us the
retention loss from applying it is larger than 5%. Anyone reading these as
"the calibrated patience" is reading them wrong. What is calibrated is the
*effort*; the patience is a quarter of it, and this stage's contribution on
that axis is the negative result that the honest p95 is unaffordable.

### Four decimal places, and why the columns are not exact quotients

The patience is the quarter **to rounding**, not exactly: `0.5665 / 4 =
0.141625`, recorded as `0.1416`. Four decimals is the precision the measurement
supports — each effort is a median over 130–160 dispatches whose per-instance
spread is several percent, so a fifth or sixth digit asserts accuracy that is
not there, and these numbers get quoted in a write-up.

The quarter is also a coincidence of *this* measurement rather than a law:
`patience_threshold` computes `min(p95, effort/4)`, which equals the quarter
only because every measured p95 came out above the ceiling. A calibration
finding a p95 *below* it would legitimately produce a smaller patience, so
nothing downstream may assume the exact relation.

### The units are not comparable across heuristics

Both options are a multiple of `nnz << 10` — vanilla HiGHS's own hardcoded
single-thread FeasibilityJump limit — so `effort = 1.0` is one vanilla FJ
budget and `patience < effort` is legible without arithmetic. But what each
heuristic's effort *counter* counts differs: FJ step units, FPR and LocalMIP
coefficient accesses, Scylla PDLP iterations x nnz. `local_mip 13.96` against
`scylla 3.07` says nothing about which searches harder.

**Scope differs too**, and this is why the numbers are valid at 16 workers and
not in general: FJ's pair sizes **one worker's** allowance, the other three
size a **whole dispatch** which `make_budget` then divides by N. Changing the
worker count therefore *reallocates* budget between heuristics rather than
rescaling it.

**97–99% of every heuristic's effort lands after its last incumbent
improvement.** That is the direct measurement of unproductive spend this probe

rather than a formality.

## Quality against best known

"Did it produce" cannot rank candidates, so each arm is also scored against the
best known objective, with `run_target`'s own `presolve_objective` and
`primal_gap` — the same functions Ablation B scores with, so a candidate cannot
score differently here than there.

| heuristic | scored | median gap | mean gap | exact | best of four |
|---|---|---|---|---|---|
| fj | 147 | **0.1102** | 0.3398 | 23 | **96** |
| local_mip | 162 | 0.2015 | 0.4140 | 21 | 88 |
| scylla | 130 | 0.4060 | 0.4955 | 14 | 46 |
| fpr | 138 | 0.6679 | 0.6045 | 10 | 37 |

**FJ leads on median gap and best-of.** 21 instances have `|reference| <= 1`,
where the capped gap saturates and the ranking falls to cost alone.

## The instance sets

**Informative set: 191 of 233 (82.0%)** — instances where a presolve heuristic
produced the reported incumbent, as a union over the four arms. Written to
`informative.txt`.

**Excluded: 42**, listed with their reasons in `report.txt`: 41
`no-acceptance` (no arm produced anything) and 1 `trivial-only` (`ex9`, where
only HiGHS's own trivial heuristics produced). No configuration cracked any of
them on this probe, which makes them constants for Ablation B's search — the
same score for every candidate, so they carry no ranking signal.

**Tuning set: 90 instances**, `bench/instances_tuning.txt`, sampled from the
informative set and stratified on **vanilla** time-to-first-feasible — not on
anything this probe measured, which is what keeps the set from being
conditioned on the outcome it will be used to compare. Largest-remainder
proportional allocation in integer arithmetic:

```
<1s 42 | 1-10s 27 | 10-100s 10 | 100-600s 6 | >=600s 1 | never 4
```

90 instances because the winner of a search over `n` configurations is biased
upward by roughly `sigma * sqrt(2 ln n)`; at a few dozen instances the
selection noise of a wide search would exceed the signal.

## Caveats that travel with these numbers

* **Valid at 16 workers only**, for the scope reason above.
* **The stale fractions conflate two wastes** — the heuristic being finished,
  and 16 workers redundantly searching after the last improvement. Separating
  them needs a single-worker control, which was not run.
* **One seed.** This is a screen: it asks whether a heuristic can *ever*
  produce on an instance, and the union over four heuristics carries most of
  the diversity a second seed would add. The quantiles are pooled over
  hundreds of dispatches.
* **Only the root dispatch is observed.** The presolve chain is re-entered for
  sub-MIPs during a full solve; a presolve-only run sees the first dispatch
  only. That is the cleanest comparable unit but it is not the whole spend.
* **The two-budget confound was not measured here.** The `budget` control mode
  exists for it; Ablation B re-measures both regimes anyway.
* **`effort` is a search centre, not an optimum.** See the bracketing ranges
  above.
